- `[x]` **P0-024.3** `TransactionBehavior` Mediator pipeline (wraps writes in TX)
  ↳ verify: [`EfUnitOfWork.cs`](./apps/api/src/EarlyEagles.Infrastructure/Persistence/EfUnitOfWork.cs) — the concrete `IUnitOfWork` the behavior was waiting on. Scoped, wraps the request's `ApplicationDbContext` connection via `Database.BeginTransactionAsync`; `EfTransaction.DisposeAsync` is what rolls back, since `TransactionBehavior` never calls Rollback explicitly — it relies on `await using` disposing an uncommitted handle. **Nested begins join rather than throw**: Npgsql has no nested transactions, so a command dispatched from inside another command's handler would make EF throw on the second `Begin`; `JoinedTransaction` makes the inner commit a no-op and the inner dispose a no-op, leaving the outermost scope the sole decider (inner success never commits work the outer scope may yet abandon; inner failure still rolls back everything). The audit log deliberately does *not* participate — `AuditService` uses its own context on its own connection (P0-047.1).
  **Behavior now gated to `ICommand`** (same cached-reflection gate `AuditBehavior` uses) — the task says "wraps *writes*", and opening a transaction around a read is a wasted round trip. Queries and plain `IRequest` pass through.
  **Now registered**: `AddApplication` pipeline is `[Logging, Audit, Validation, Transaction]` — Transaction innermost, so a validation failure throws before any transaction opens and the audit row lands outside the transaction that just rolled back. `AddInfrastructure` binds `IUnitOfWork -> EfUnitOfWork` scoped.
  Tests: [`TransactionBehaviorTests.cs`](./apps/api/tests/EarlyEagles.Tests.Unit/Behaviors/TransactionBehaviorTests.cs) grew to 7 (added query pass-through, plain-`IRequest` pass-through, non-generic `ICommand` is wrapped — Mediator's `ICommand` and `ICommand<T>` are separate interfaces). [`EfUnitOfWorkTests.cs`](./apps/api/tests/EarlyEagles.Tests.Integration/Persistence/EfUnitOfWorkTests.cs) — 6 real-Postgres tests proving the EF layer actually commits and rolls back: commit persists; dispose-without-commit discards; a handler that writes then throws (driven through the real behavior) leaves nothing; a successful command commits; a nested join isn't durable until the outer commits; a nested join is undone when the outer abandons. Reads verify on a **separate** context so they only see committed rows. 189 unit + 70 integration pass.

- `[x]` **P0-050.2.1** Drain publishes each pending row through `IOutboxPublisher` and stamps the outcome
  ↳ verify: [`IOutboxPublisher.cs`](./apps/api/src/EarlyEagles.Infrastructure/Outbox/IOutboxPublisher.cs) — the port, in Infrastructure rather than beside the Application ports for the same reason `OutboxMessage` is: transport machinery, no Application consumer, one caller. `OutboxProcessor.DrainOnceAsync` replaces `PollOnceAsync`: **one scope for the whole drain**, because the messages have to stay tracked by the context that will save their stamps. Per message: publish → `MarkProcessed(utcNow)`; on failure → `RecordFailure(type + message)` and carry on. One `SaveChanges` for the batch — the stamps are bookkeeping about work already done, so there is nothing to roll back if a later message fails.
  New state transitions on [`OutboxMessage`](./apps/api/src/EarlyEagles.Infrastructure/Outbox/OutboxMessage.cs): `MarkProcessed` refuses a second stamp (double delivery is a drain bug, not something to absorb quietly) and clears `LastError` (it described the attempt that failed and no longer describes anything); `RecordFailure` bumps `AttemptCount`, truncates at 2000 chars rather than rejecting — diagnostic text, better clipped than lost — and refuses to run on a delivered row.
  **Trade-off pinned by a test:** one unpublishable message does *not* hold up the batch, so while it keeps failing, later messages are delivered ahead of it — strict ordering is not preserved across a failure. Availability is worth more than order here; a dead-letter policy for poison messages comes with the real bus.
  **At-least-once, deliberately:** the row is stamped only *after* a successful publish, so a process that dies in between re-sends on the next tick. A lost event is worse than a repeated one, and the port documents that implementations must tolerate it.
  [`LoggingOutboxPublisher`](./apps/api/src/EarlyEagles.Infrastructure/Outbox/LoggingOutboxPublisher.cs) is the registered placeholder (same shape as `NullTenantLookup`) — it logs and reports success, so the whole path is exercisable on a laptop with no Azure account. **While it is registered, events are marked processed without reaching any bus.** Swapping it for the real one is a registration change.
  10 new unit tests on the row's state machine + 3 new integration tests (published row stamped and gone from the queue; failed row pending with attempt counted, retried next tick; one bad message doesn't block the batch); the 4 existing query tests now drive `DrainOnceAsync` through a recording publisher. 214 unit + 84 integration pass.
